# Sabor-App — продуктовый обзор

## Назначение
Sabor-App — внутреннее приложение **для сотрудников ресторана** (официанты/администраторы). Основная цель — быстро дать сотруднику нужную информацию (меню, составы, аллергены, pairing’и, справка), помочь обучению (тренажёр/вопросы), и предоставить админ‑инструменты управления контентом/видимостью.

## Основные модули
- **Меню**: кухня / вино / бар / чай (данные живут в `data/*.json`, см. `data.md`).
- **Справочные материалы / полезные статьи**: private‑контент (на деплое кладётся в `backend/private/useful_guides`).
- **Тренажёр**: загрузка данных из `/data/*.json`, режимы вопросов/ответов.
- **Уведомления** (“колокольчик”): создаются админом, видны пользователям; умеют истекать по времени.
- **VisibilityConfig (feature flags / правила видимости)**: версионируемые правила allow/deny по scope/target.
- **Обратная связь**: сообщения **от сотрудников** (например, от официантов) через форму/интерфейс; поддерживаются вложения; опционально уведомление в Telegram.
- **Админ‑панель**: пользователи, меню‑импорт/редактирование, visibility, notifications, просмотр feedback, статистика.

## Роли и доступ
- **Администратор**: доступ к админ‑API (`/api/admin/*`), управляет пользователями/visibility/уведомлениями.
- **Официант / пользователь**: основная аудитория; использует меню/тренажёр/справку; может отправлять feedback.
- **Гостевой режим (read‑only)**: существует как технический режим ограниченного доступа (см. `backend/routes/auth.py`). Это не “публичное приложение для гостей”, а режим с урезанными данными и запретом на запись.

## Ключевые принципы (как “на самом деле работает”)
- **Источник правды по контенту** — JSON в `data/` (меню/сравнения/вопросы/конфиг групп). Эти файлы на деплое копируются в `frontend/public/data/` и доступны как статика.
- **SQLite** используется для API/админ‑операций, но в проде она **пересобирается из JSON** (`backend/migrate_to_db.py`) — поэтому формат JSON и уникальность `id` критичны.
- **Надёжность меню на фронте**: основной источник — API, но есть fallback на статические JSON и кэш браузера (см. `frontend/src/services/api.js`).

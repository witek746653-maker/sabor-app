## Что это за проект (1 абзац)
**Sabor-App** — внутреннее веб‑приложение **для сотрудников ресторана** (в первую очередь официантов). Оно даёт доступ к меню (кухня/вино/бар/чай), справочным материалам/тренажёру, админ‑функциям (пользователи, видимость/фичи, уведомления) и сбору “обратной связи” **от сотрудников** (например, вопросы/заметки/сообщения с вложениями), с опциональной отправкой в Telegram.

## Как “скармливать” в LLM (чтобы не забивать контекст)
Рекомендуемый набор файлов зависит от задачи:
- **Ориентация в проекте:** `overview.md` + `devops.md`
- **Работа с меню/контентом:** `data.md` (+ при необходимости `api.md`)
- **Работа с API/бэкендом:** `api.md` + `devops.md` (+ `data.md`)
- **Фронтенд‑правки:** `frontend.md` + `api.md` (+ `data.md` если меняете меню)
- **Деплой/прод‑инцидент:** `devops.md` (+ `api.md` если затронуты ручки)
- **Тесты:** `testing.md`

## Файлы спецификации
- `overview.md` — продуктовое описание: для кого, какие модули, роли/доступ, ключевые принципы.
- `devops.md` — стек, структура репо, запуск локально, конфиги/секреты, деплой, правила изменений.
- `data.md` — **источник правды** `data/*.json`: схемы файлов + правила/инварианты + связь с SQLite.
- `api.md` — контракты API + автосгенерированный список routes.
- `frontend.md` — фронтенд‑особенности (источники меню в dev, прокси, важные модули).
- `testing.md` — тестирование и инструменты (в т.ч. WebTester).

## Как поддерживать актуальность
- Быстро: `python tools/update_knowledge.py` или `powershell -ExecutionPolicy Bypass -File .\\tools\\update_knowledge.ps1`
  - обновляет дату (в файлах с маркерами) и список API routes (в `api.md`).
- При изменениях форматов JSON/контрактов API/деплоя — обновляйте соответствующий файл вручную.

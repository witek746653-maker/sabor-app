# 🏗 Архитектура и Логика Sabor-App

Этот документ описывает устройство, технологии и логику работы приложения Sabor-App. Используйте его как базу знаний для понимания проекта.

---

## 1. Обзор Проекта

**Sabor-App** — это веб-приложение для ресторана, выполняющее функции:
1.  **Электронное меню**: Интерактивный каталог блюд, вин и напитков с фильтрацией и поиском.
2.  **Обратная связь**: Система сбора отзывов и вопросов от гостей (с фото и тегами).
3.  **Админ-панель**: Управление стоп-листами, редактирование меню, просмотр статистики и сообщений.

Приложение реализовано как **монолит** с четким разделением на Frontend (SPA) и Backend (API), работающих в связке.

---

## 2. Технологический Стек

### 🎨 Frontend (Клиентская часть)
*   **Фреймворк**: [React 18](https://react.dev/) (Create React App).
*   **Язык**: JavaScript (ES6+).
*   **Стилизация**: [Tailwind CSS](https://tailwindcss.com/) (утилитарные классы).
*   **Роутинг**: `react-router-dom` v6 (SPA навигация без перезагрузки).
*   **Взаимодействие с API**: `axios` (HTTP-клиент).
*   **Состояние**: React Context API (локальное хранилище данных).
*   **Icon Pack**: `lucide-react`.

### 🧠 Backend (Серверная часть)
*   **Фреймворк**: [Flask](https://flask.palletsprojects.com/) (Python).
*   **База данных**: SQLite (файловая БД, легковесная и надежная).
*   **ORM**: SQLAlchemy (работа с БД через Python-классы).
*   **Аутентификация**: `Flask-Login` (сессии, хеширование паролей).
*   **Сервер приложений**: Gunicorn (в продакшене) / Werkzeug (локально).

### 🛠 Инфраструктура и DevOps
*   **ОС Сервера**: Linux (Ubuntu/Debian) на хостинге Beget.
*   **Веб-сервер**: Nginx (раздает статику фронтенда и проксирует API запросы на Flask).
*   **Process Manager**: Systemd (управляет службой `sabor.service` — автозапуск бэкенда).
*   **Скрипты**: PowerShell (`.ps1`) для автоматизации деплоя и синхронизации БД.

## 4. Архитектура Данных и Потоки (Data Flow)

Приложение использует **Гибридную модель данных** для максимальной отказоустойчивости.

### 🔄 Режимы работы с данными (Frontend)
Логика загрузки меню (`frontend/src/services/api.js`) работает по приоритетам:

1.  **Backend API + DB (Основной)**:
    *   Фронтенд запрашивает `/api/dishes`.
    *   Бэкенд берет данные из SQLite.
    *   Это позволяет динамически управлять стоп-листами и скрывать позиции без пересборки приложения.

2.  **Static JSON (Резервный/Static)**:
    *   Если API недоступен (ошибка 500/сеть), фронтенд автоматически переключается на загрузку статических файлов из `/data/menu-kitchen.json`.
    *   Эти файлы лежат в папке `public` и раздаются Nginx как обычная статика.
    *   **Гарантия работы**: Даже если `backend` (Python) упал, гости могут видеть меню.

3.  **LocalStorage Cache (Офлайн)**:
    *   Если нет ни API, ни статики (нет интернета), приложение показывает последнюю сохраненную версию из кэша браузера.

## 5. База Данных (Schema)

Используется SQLite. БД разделена на два контура:
1.  **Dev** (`backend/database.dev.db`): Для локальных экспериментов.
2.  **Prod** (`/var/lib/sabor-app/database.db`): Реальные данные на сервере.

**Основные Модели (`models.py`):**

*   **Меню**: `Dish`, `KitchenItem`, `WineItem`, `BarItem`, `TeaItem`.
    *   Хранят: `title`, `description`, `price`, `image` (путь), `tags` (JSON), `allergens` (JSON).
*   **Пользователи**: `User`.
    *   Роли: `admin`, `waiter`, `guest`.
    *   Пароли хранятся в зашифрованном виде (PBKDF2).
*   **Обратная связь**: `FeedbackMessage`.
    *   Типы: вопрос, жалоба, предзаказ.
    *   Вложения (фото) хранятся на диске, ссылки в БД.
*   **Конфигурация**: `VisibilityConfig`.
    *   Позволяет "на лету" включать/выключать разделы меню через админку (Feature Flags).

## 6. Ключевые Модули

### 🍷 Каталог и Фильтрация
*   Данные загружаются на клиент целиком (Client-side filtering).
*   Фильтрация происходит мгновенно на JS (по тегам, категориям, ингредиентам).
*   Картинки подгружаются лениво (`loading="lazy"`).

### 🔐 Аутентификация и Гостевой Режим
*   **Гость**: Видит общедоступное меню. Некоторые разделы (например, винная карта) могут быть скрыты.
*   **Администратор**: Входит по логину/паролю. Получает токен (cookie сессии). Видит кнопки редактирования и админ-панель (`/admin`).
*   **Guest Blocker**: Компонент React, который скрывает контент или показывает "заглушку", если у пользователя нет прав.

### 🚀 Деплой и CI/CD (Workflow)
Процесс выкладки автоматизирован через скрипт `deploy.ps1`:
1.  **Локально**:
    *   Компиляция React (`npm run build`).
    *   Генерация статики.
2.  **Транспорт**:
    *   Файлы копируются на сервер через `SCP` (SSH).
3.  **На Сервере**:
    *   Бэкенд перезапускается (`systemctl restart sabor`).
    *   Новые статические файлы подхватываются Nginx.

## 7. Полезные Команды

*   `.\dev` — Запуск всего проекта локально (Frontend + Backend + Sync DB).
*   `npm start` — Запуск только фронтенда (порт 3000).
*   `.\deploy.ps1` — Выкладка изменений на продакшн.
*   `ssh sabor` — Вход на удаленный сервер.

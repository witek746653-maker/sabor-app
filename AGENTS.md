# Sabor-app — правила для Codex

Эти инструкции относятся к этому репозиторию и должны соблюдаться при любых изменениях кода.

## Структура проекта
- Не смешивать фронтенд и бэкенд код.
- Не создавать новые папки верхнего уровня без явной необходимости; по возможности добавлять файлы в существующие директории.
- Фронтенд находится в `frontend/`, бэкенд — в `backend/`.

## Контекст и стек (технические ограничения)
- Приложение fullstack:
  - frontend: React (Create React App) + React Router + Tailwind
  - backend: Flask API + SQLite + Flask-Login (cookie sessions)
- В продакшене фронтенд и бэкенд на одном домене: фронтенд обращается к API относительными путями вида `/api/...`.
- В деве фронтенд использует proxy на бэкенд (обычно `localhost:5000`).
- Предпочитать небольшие, безопасные изменения, не ломающие существующие роуты и админку.

## Данные меню (DB + JSON fallback)
- Источник редактирования/админки: SQLite (через SQLAlchemy).
- `menu-database.json` используется как fallback и может содержать дополнительные поля.
- При изменении полей меню держать DB и JSON согласованными; не удалять “дополнительные” поля (например wine/bar), которые приходят из JSON.
- При импорте/пересборке: дедуплицировать по `id`, сохранять ожидаемый UI порядок, не ломать fallback (меню должно показываться даже при частичном сбое DB).

## Безопасность и деплой
- Никогда не коммитить секреты: `SECRET_KEY`, токены, пароли — только через env vars.
- Во фронтенде использовать только публично-безопасные переменные `REACT_APP_*`.
- UI-деплой по умолчанию считать выключенным; если трогаете деплой-логику — оставлять её строго защищённой флагом `ADMIN_DEPLOY_ENABLED=true` и секретом `DEPLOY_ADMIN_TOKEN`.
- Для upload’ов: валидировать тип/размер, использовать безопасные имена файлов, не доверять пользовательским путям.

## Автотесты (обязательное обновление при изменениях)
- При добавлении новых React-компонентов в `frontend/src/components/` или новых эндпоинтов в `backend/`:
  - обновлять сценарии проверки в `tools/tests/test_agent.py`;
  - обновлять список проверяемых страниц для WebTester (сейчас он находится в `tools/tests/admin_diag.py`).
